# Build 45 remaining gates and limits

- Source candidate only. Both Android Gradle builds could not download Gradle in this environment. No APK compilation success is claimed. Admin browser execution was blocked by unavailable Chromium; browser download failed. PostgreSQL runtime/integration/restore could not run because psycopg and a disposable PostgreSQL service were unavailable. CI must pass before deployment.
- Both phone apps, Google tiles/routing, background/restart/reconnect, accessibility and deployed Render latency require acceptance. Existing free-host cold starts and serialized API throughput remain.
- Staging offers need a server-only Routes key and successful road response. A missing key stops offers. No provider account/billing/key was configured here. Default staging pickup limits are 15 km/30 min; the long BC Place test needs a deliberate test override.
- GPS chord-sum distance is provisional. Every ended assignment needs verified actual distance with an evidence-based Admin review. Missing or inaccurate GPS cannot be reconstructed automatically. Cross-period/rate-boundary distance and earnings use time-proportional allocation, flagged for payroll review.
- No automatic historical compensation backfill. Finish Build 44 active rides before upgrading; otherwise those assignments will lack a Build 45 acceptance record. Audit earlier work separately.
- Finalized periods are immutable. A correction/dispute workflow and regulatory payroll exports/tax statements are not implemented. The period tool writes test ledger entries only, not payouts.
- Tips are not connected to a verified settlement flow. The current report shows recorded tips as zero. Daily completed-trip history remains base earnings; the separate pay-period section includes this build's full provisional accounting.
- Server route requests occur under existing serialized dispatch and are capped per process, not globally across workers. Google-side quota controls are required. Route snapshots in offers expire; navigation can recalculate a different route later.
- Live boost UX is new source code requiring device testing. No zones were enabled/funded. Boost award rules now use acceptance-time reservation, not the legacy completion-time budget race.
- Legal/commercial readiness is not established by passing tests. Qualified BC employment/payroll, transportation, insurance, tax, privacy and accessibility review remains a launch requirement.

Earlier Build 44 limitations concerning notifications, document verification, large-scale evidence retention and emergency services still apply; see DATA_RETENTION_BUILD_44.md and BC_COMPLIANCE_REVIEW_BUILD_44.md for historical context.
